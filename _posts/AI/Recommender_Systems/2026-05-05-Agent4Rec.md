**On Generative Agents in Recommendation**  
(An Zhang, Yuxin Chen, Leheng Sheng, Xiang Wang, Tat-Seng Chua, SIGIR, 2024)
{: .notice--info}

## 초록 
### 1. 연구 배경 및 문제의식
- 오프라인 평가 지표와 실제 온라인 성능 사이에 차이가 큼
- 이로 인해 실제 사용자의 행동, 감정, 만족도를 충분히 반영하기 어려움
- 따라서 학계 연구 결과가 실제 서비스 환경에 바로 적용되기 어려움

### 2. 연구 목적
실제 사용자처럼 행동하는 추천 시뮬레이터를 만드는 것이 목표 <br>(=Agent4Rec,  LLM 기반 사용자 시뮬레이터)<br> <br>

핵심 연구 질문 : <br>
<span style="color: blue">LLM 기반 생성형 에이전트(Agent4Rec)가 추천시스템 안에서 실제 인간 사용자의 행동을 얼마나 충실하게 모방할 수 있는가?</span>

### 3. Agent4Rec
LLM 기반 생성형 에이전트를 활용한 추천시스템 사용자 시뮬레이터 <br> <br>
- 실제 데이터셋으로 초기화된다 (예 : MovieLens, Steam, Amazon-Book 등)
<br> <br>

**[Agent4Rec의 주요 모듈]**

| 모듈 | 역할 |
|---|---|
| Profile module | 사용자의 취향, 사회적 특성, 과거 선호를 저장 |
| Memory module | 사용자의 행동, 감정, 피로도, 시스템 상호작용을 기억 |
| Action module | 추천 아이템에 대해 시청, 무시, 평점 부여, 의견 표현 등의 행동 수행 |

- 에이전트는 추천시스템이 제공하는 아이템 목록을 페이지 단위로 확인
- 추천 알고리즘은 협업 필터링 기반 방식으로 구현
- 에이전트는 추천 결과에 대해 실제 사용자처럼 반응
  
### 4. 실험 및 분석 요약 
- 실제 사용자 선호와 에이전트 행동의 정렬성 평가
- 추천 알고리즘의 오프라인 성능 평가
- 시뮬레이션 피드백을 활용한 추천 전략 개선
- 필터 버블 효과 재현
- 추천시스템 내 인과관계 분석

> Agent4Rec은 단순한 추천 성능 비교 도구가 아니라 사용자 행동을 시뮬레이션하고, 추천 과정에서 발생하는 문제를 분석할 수 있는 실험 플랫폼이라는 점에서 의의가 있다 !


## Introduction
### 1. 추천시스템의 중요성
- 추천시스템은 현대 정보 확산에서 중요한 역할을 한다.
- 사용자가 어떤 정보를 접하고, 무엇을 선호하게 되는지에도 영향을 미친다. <br>
(개인의 콘텐츠 소비 방식 형성 / 사용자 선호 변화 유도 / 정보 노출 방식 결정 / 인지 과정에 영향 등)

### 2. 기존 연구의 한계
기존 추천시스템 연구는 주로 오프라인 평가 지표에 의존하는데, 오프라인 성능이 높다고 해서 실제 서비스에서도 좋은 성능 보장은 X <br> <br>

| 구분 | 설명 |
|---|---|
| 오프라인 평가 | 과거 데이터셋을 기반으로 추천 성능을 측정 |
| 온라인 성능 | 실제 사용자가 추천 결과에 어떻게 반응하는지 측정 |
| 문제점 | 두 평가 결과 사이에 큰 차이가 발생할 수 있음 |

<br>
이로 인해 .. <br>
- 학계 연구가 실제 서비스에 적용되기 어려움
- 추천 알고리즘 개발 속도 저하
- 실제 사용자 반응을 반영하기 어려움

### 3. 추천 시뮬레이터의 필요성
실제 사용자의 의도와 행동을 반영할 수 있는 추천 시뮬레이터가 필요하다 !!
<br> <br> 그런데 최근 LLM은 인간과 유사한 언어 이해 및 추론 능력을 보여주고 있다 <br>
-> 이러한 LLM을 기반으로 생성형 에이전트를 만들어 추천 환경 안에서 가상의 사용자 역할을 수행하도록 하자 !!<br> <br>

**중요 포인트** <br>
- 개인화된 사용자 선호를 정확히 반영해야 함
- 실제 사람처럼 일관된 행동을 해야 함
- 감정, 피로도, 기억, 과거 경험 등을 반영해야 함

### 4. Agent4Rec의 전체 구조

| 구성 요소 | 설명 |
|---|---|
| LLM 기반 생성형 에이전트 | 실제 사용자처럼 행동하는 가상 사용자 |
| 추천 환경 | 추천 알고리즘이 아이템을 제공하고 에이전트가 반응하는 공간 |

<span style="background-color: #fff3cd">이 중 사용자 에이전트 부분 :</span> <br>
- 각 추천 시나리오마다 1,000개의 LLM 기반 에이전트를 생성
- 각 에이전트는 실제 데이터셋을 기반으로 초기화
- 에이전트는 세 가지 핵심 모듈 O
<br>

1.  Profile Module<br>
- 사용자의 사회적 특성, 과거 선호 저장
- 실제 인간 사용자와 유사한 사용자 초상 구성
  <br>
2.  Memory Module<br>
- 과거 시청 기록, 추천시스템과의 상호작용 기록, 감정 (사용자의 피로도 등) 등을 기억
- 선호 누적 및 감정 기반 반성 수행
  <br>
3.  Action Module<br>
- 추천 환경과 직접 상호작용
- 취향 기반 행동(추천 영화 보기, 무시하기, 평점 매기기 등)과 감정 기반 행동(시스템 종료, 추천 목록 평가, 의견 표현)을 모두 수행
<br>



<span style="background-color: #fff3cd">그리고 추천시스템 부분 : </span> <br>
미리 정해진 추천 알고리즘(LightGCN,MultVAE 등)에 의존 <br>
주로 CF 기반 추천 알고리즘을 사용하며, <br> 개방형 인터페이스를 제공해서 다른 추천 알고리즘도 쉽게 적용할 수 있다.

## Agent4Rec

### 1. Agent

<span style="color: blue">Agent는 실제 사용자처럼 추천 아이템에 반응하도록 설계된 가상 사용자</span>이다.  <br>
각 에이전트는 실제 사용자 데이터를 바탕으로 생성되며, 개인 취향, 사회적 특성, 기억, 행동 능력을 가진다.<br><br>

**1) Profile Module**
<br>
Profile Module은 사용자의 개인화된 특성과 취향을 저장하는 모듈이다.<br>

- 사회적 특성
  - Activity: 사용자가 추천된 아이템과 얼마나 자주, 폭넓게 상호작용하는지
    - 수식: $T_{act}^{u} = \sum_{i \in \mathcal{I}} y_{ui}$
    - 즉, 사용자 $u$가 상호작용한 item 개수를 의미한다.
    - <span style="background-color: #fff3cd">값이 클수록 더 활동적인 사용자</span>로 볼 수 있다.

  - Conformity: 사용자의 평점이 전체 평균 평점과 얼마나 비슷한지
    - 수식: $T_{conf}^{u} = \frac{1}{\sum_{i \in \mathcal{I}} y_{ui}} \sum_{i \in \mathcal{I}} y_{ui} \cdot |r_{ui} - R_i|^2$
    - 여기서 $r_{ui}$는 사용자 $u$가 item $i$에 준 평점이고, $R_i$는 item $i$의 평균 평점이다.
    - <span style="background-color: #fff3cd">값이 작을수록 사용자의 평점이 평균 평점과 가깝다</span>, 즉 대중의 평가와 비슷하다고 볼 수 있다.

  - Diversity: 사용자가 얼마나 다양한 장르의 item과 상호작용했는지
    - 수식: $T_{div}^{u} = |\cup_{i \in \{y_{ui}=1\}} G_i|$
    - 여기서 $G_i$는 item $i$가 속한 장르 집합이다.
    - <span style="background-color: #fff3cd">값이 클수록 더 다양한 장르를 소비하는 사용자</span>로 볼 수 있다.

- 고유 취향
  - 사용자마다 시청 이력에서 25개 item을 랜덤 선택한다.
  - 평점 3 이상은 Like, 평점 3 미만은 Dislike로 구분한다.
  - ChatGPT가 사용자의 취향을 자연어로 요약한다.
  - 요약된 취향을 Profile에 반영한다.

<span style="background-color: #fff3cd">이때 이름, 나이 등 개인정보는 사용하지 않는다.</span>
<br><br>

**2) Memory Module**
<br>
Memory Module은 과거 상호작용과 감정을 저장하는 모듈이다.<br>

- Factual Memory
  - 추천시스템 안에서 발생한 사실적인 행동을 저장한다.
  - 예: 과거 추천 목록, 아이템 시청 여부, 평점 기록 등

- Emotional Memory
  - 추천 과정에서 발생한 감정적 기억을 저장한다.
  - 예: 추천 만족도, 피로도 등

기억은 자연어 설명과 벡터 표현으로 저장된다.<br><br>

Memory Module에는 세 가지 operation이 있다.
<br>
- Memory Retrieval
  - 현재 추천 판단에 필요한 관련 기억을 검색한다.

- Memory Writing
  - 에이전트의 상호작용과 감정을 기록한다.

- Memory Reflection
  - 일정 행동 수를 넘으면 추천 만족도와 피로도를 점검한다.
  - 감정이 이후 추천 판단에 미치는 영향을 반영한다.
<br><br>

**3) Action Module**
<br>
Action Module은 Profile과 Memory를 바탕으로 에이전트가 실제 사용자처럼 행동하도록 만드는 모듈이다.

- Taste-driven Actions
  - 취향을 바탕으로 행동한다.
  - 예: 추천 item을 보거나 무시하기, rating 부여, 시청 후 감정 생성

- Emotion-driven Actions
  - 감정을 바탕으로 행동한다.
  - 예: 다음 페이지로 이동, 추천 시스템 종료, 추천 만족도 평가, 종료 후 인터뷰 수행

> A. 사실 이부분은 잘 대답을 하지 못하였다. 고민이 필요한 부분인듯하다. 

### 2. Recommendation Environment

Recommendation Environment는 <span style="color: blue">에이전트와 추천시스템이 상호작용하는 환경</span>이다.<br><br>

**1) Item Profile Generation**

추천 item의 주요 정보를 구성한다.

- Quality: 과거 평점 기반 item 품질
- Popularity: 리뷰 수 또는 상호작용 수 기반 인기도
- Genre: item 장르
- Summary: item 요약

> **[교수님께서 질문하신 부분]**<br><br>
> Q. 페이지 단위로 Item Profile Generation할 때 Summary 같은게 왜 필요한가? <br><br>
> A. item title 만으로 실제 사용자는 배경지식이 있다보니 그게 뭔 영화인지 추측하고 보거나 말거나할 수 있지만 LLM은 그게 안될수도 있으므로 summary를 만드는 것이다

Genre와 Summary는 LLM이 item title을 기반으로 생성한다.  <br>
<span style="background-color: #fff3cd">LLM의 genre 분류가 실제 데이터와 다르면 해당 item을 제거하여 hallucination 위험을 줄인다.</span><br><br>

**2) Page-by-Page Recommendation Scenario**

실제 추천 플랫폼처럼 페이지 단위로 추천을 진행한다.<br>

과정은 다음과 같다.<br>

1. 추천 item 확인
2. 볼 item 선택 또는 무시
3. 평점 부여
4. 다음 페이지 이동 또는 종료 선택
<br><br>

**3) Recommendation Algorithm Designs**

Agent4Rec은 다양한 추천 알고리즘이 연결 가능한 구조로 설계되었다.<br>

사용 가능한 추천 알고리즘 예시는 다음과 같다.

- Random
- Popularity
- MF
- MultVAE
- LightGCN

목적은 <span style="color: blue">여러 추천 전략을 같은 시뮬레이션 환경에서 비교하고 평가하는 것</span>이다.<br>

## 실험

### 1. Agent Alignment Evaluation

![Agent4Rec_result1](/assets/images/Agent4Rec_result1.png) 

**Motivation**

<span style="color: blue">에이전트는 실제 사용자가 과거에 좋아했거나 상호작용했던 item을 잘 구별할 수 있는가?</span>

**Setting**

- 데이터셋: MovieLens-1M, Steam, Amazon-Book
- 각 데이터셋에서 1,000명의 에이전트를 생성
- 각 에이전트에게 20개의 item을 제시
- 상호작용한 item과 상호작용하지 않은 item의 비율을 1:1 , 1:2, 1:3, 1:9로 조정

**Results**

- Accuracy는 대체로 약 65% 수준이었다.
- Recall은 약 75% 수준이었다.
- 에이전트가 실제 사용자 선호와 맞는 아이템을 어느 정도 잘 찾아낸다.
- 그러나 방해 item이 많아질수록 Precision과 F1 Score가 크게 감소했다.

<span style="background-color: #fff3cd">이는 에이전트가 실제로는 사용자가 좋아하지 않을 item도 좋아할 것이라고 판단하는 경우가 많아졌다는 뜻이다.</span>  <br>
논문에서는 이를 LLM의 hallucination 문제와 연결하여, 에이전트가 상황과 관계없이 일정 수의 item을 선호한다고 판단하는 false positive 경향이 있기 때문이라고 설명한다.
<br><br>
관련 지표는 다음과 같다.

- $Accuracy = \frac{TP + TN}{TP + TN + FP + FN}$
- $Precision = \frac{TP}{TP + FP}$
- $Recall = \frac{TP}{TP + FN}$
- $F1 = \frac{2 \times Precision \times Recall}{Precision + Recall}$

- Random

- MF
- MultVAE
- LightGCN

실험 과정은 다음과 같다.

1. 한 추천 페이지에 영화 4개를 제시한다.
2. 에이전트는 각 페이지에서 영화를 볼지 결정하고 평점을 부여한다.
3. 만족도에 따라 다음 페이지로 갈지, 시스템을 나갈지 결정한다.
4. 최대 5페이지까지 탐색한다.
5. 종료 후 추천시스템 만족도를 1~10 점으로 평가한다.

**Results**

- 에이전트는 Random이나 Popularity 기반 추천보다 알고리즘 기반 추천에 더 높은 만족도를 보였다.
- <span style="background-color: #fff3cd">LightGCN이 여러 지표에서 가장 좋은 결과를 보였다.</span>

평가 지표는 다음과 같다.

- $\bar{P}_{view}$: 추천 item을 본 비율
- $\bar{N}_{like}$: 좋아요 개수
- $\bar{P}_{like}$: 좋아요 비율
- $\bar{N}_{exit}$: 평균 이탈 페이지
- $\bar{S}_{sat}$: 추천시스템 만족도

### 5. Page-by-Page Recommendation Enhancement

![Agent4Rec_result7](/assets/images/Agent4Rec_result7.png) 

**Motivation**

<span style="color: blue">Agent4Rec에서 생성된 사용자 피드백을 추천 모델 개선에 활용할 수 있는가?</span>

**Setting**

시뮬레이션이 끝난 뒤, 각 에이전트에 대해 두 종류의 item을 수집한다.

- Viewed item: 에이전트가 실제로 본 item
- Unviewed item: 에이전트가 추천받았지만 보지 않은 item

이후 각각을 positive signal로 간주하여 training set에 추가한 뒤 추천 알고리즘을 다시 학습한다.

평가는 오프라인 지표와 시뮬레이션 만족도 지표로 진행한다.

- 오프라인 지표: $Recall@20$, $NDCG@20$
- 시뮬레이션 만족도 지표: $N_{exit}$, $S_{sat}$

**Results**

- <span style="background-color: #fff3cd">Viewed item을 학습 데이터에 추가했을 때 성능이 향상되었다.</span>
- <span style="background-color: #fff3cd">Unviewed item을 positive signal로 추가했을 때는 성능이 악화되었다.</span>

즉, 에이전트가 실제로 본 item은 추천 모델 개선에 유용한 피드백이 될 수 있지만, 단순히 노출되기만 하고 보지 않은 item은 긍정 피드백으로 사용하면 오히려 성능을 떨어뜨릴 수 있다.

## 추가 실험

### 1. Filter Bubble Effect

![Agent4Rec_result9](/assets/images/Agent4Rec_result9.png)

**Motivation**

추천시스템은 사용자의 과거 피드백을 바탕으로 비슷한 item을 반복 추천할 수 있다.  
이로 인해 <span style="color: blue">사용자가 다양한 item을 접할 기회가 줄어드는 filter bubble 문제</span>가 발생할 수 있다.

**Setting**

- MovieLens 영화 pool을 $4$개 부분으로 나눈다.
- MF 기반 추천기를 사용한다.
- 총 $4$번의 시뮬레이션을 반복한다.
- 각 round마다 최대 $5$페이지를 추천한다.
- 각 round 후 추천기를 다시 학습한다.
- 추천 장르 다양성 변화를 측정한다.

**Result**

- 반복이 증가할수록 추천 결과가 점점 특정 장르에 집중되었다.
- Top-1 genre 비율이 증가했다.
- 추천 장르 수는 감소했다.
- <span style="background-color: #fff3cd">Agent4Rec이 실제 추천시스템에서 나타나는 filter bubble 현상을 재현할 수 있음을 보였다.</span>

### 2. Discovering Causal Relationships

![Agent4Rec_result10](/assets/images/Agent4Rec_result10.png)

**Motivation**

추천시스템에서는 평점, 인기도, 노출, 시청 수 사이의 관계가 복잡하다.  
<span style="color: blue">Agent4Rec으로 생성한 시뮬레이션 데이터를 활용하면 추천 과정 안의 숨겨진 인과관계를 탐색할 수 있다.</span>

**Setting**

MovieLens의 각 영화에 대해 다음 정보를 수집한다.

- Movie Quality
- Movie Popularity
- Exposure Rate
- View Number
- Movie Rating

이후 DirectLiNGAM 알고리즘을 사용해 인과 그래프를 학습한다.

**Result**

- 영화 평점은 주로 영화 품질의 영향을 받았다.
- 영화 인기도도 영화 평점에 일부 영향을 주었다.
- <span style="background-color: #fff3cd">인기 영화가 더 많이 노출되고, 더 많이 시청되는 피드백 루프가 관찰되었다.</span>

즉, Agent4Rec은 단순히 추천 알고리즘을 평가하는 데 그치지 않고, 추천시스템 내부에서 발생하는 구조적 문제나 인과관계를 탐색하는 데에도 활용될 수 있다.

## 결론

### 1. 공헌

Agent4Rec의 주요 공헌은 다음과 같다.

1. <span style="color: blue">LLM 기반 생성형 에이전트를 추천시스템의 가상 사용자로 활용하는 Agent4Rec을 제안했다.</span>

2. 여러 추천 알고리즘을 같은 환경에서 비교할 수 있는 시뮬레이션 프레임워크를 제시했다.

3. 기존의 $Recall$이나 $NDCG$ 같은 오프라인 지표만 본 것이 아니라, 사용자 경험 중심 지표를 함께 평가했다.

사용자 경험 중심 지표에는 다음이 포함된다.

- 추천 item을 본 비율
- 좋아요 개수와 비율
- 평균 이탈 페이지
- 추천시스템 만족도
- 종료 후 자연어 인터뷰

4. Agent feedback을 추천 모델 개선에 활용할 수 있음을 보였다.

5. <span style="background-color: #fff3cd">실제 A/B test처럼 비용 부담이 큰 실험을 하기 전에 사전 평가 도구로 활용될 가능성을 보였다.</span>

### 2. 한계

Agent4Rec의 한계는 다음과 같다.

1. <span style="background-color: #fff3cd">LLM hallucination 문제가 존재한다.</span><br>
Agent Alignment Evaluation에서 false positive 경향이 나타났다.  
즉, 에이전트가 실제 사용자가 좋아하지 않을 item도 좋아할 것이라고 판단하는 경우가 있었다.


2.  <span style="background-color: #fff3cd">낮은 평점을 주는 인간 행동을 충분히 모방하지 못했다.</span><br>
Rating Distribution Alignment에서 전체적인 평점 분포는 실제 사용자와 유사했지만, 에이전트는 실제 사용자보다 $1 \sim 2$점의 낮은 평점을 훨씬 적게 주었다.


3.  <span style="background-color: #fff3cd">오프라인 데이터셋 기반이라는 한계가 있다.</span><br>
MovieLens, Steam, Amazon-Book 같은 오프라인 데이터셋을 기반으로 하기 때문에 실제 온라인 환경의 사용자 반응을 완전히 반영하기는 어렵다.

### 3. 최종 정리

<span style="color: blue">Agent4Rec은 LLM 기반 생성형 에이전트를 가상 사용자로 활용하여 추천시스템을 평가하는 프레임워크이다.</span>  
기존 오프라인 지표 중심 평가에서 벗어나, 사용자의 시청 여부, 만족도, 이탈, 감정, 자연어 인터뷰까지 포함해 추천 품질을 더 입체적으로 분석할 수 있다.

하지만 LLM hallucination, 낮은 평점 재현의 어려움, 오프라인 데이터셋 기반이라는 한계가 존재한다.  
<span style="background-color: #fff3cd">따라서 Agent4Rec은 실제 사용자를 완전히 대체하는 도구라기보다는, 실제 A/B test 이전에 추천 전략을 사전 검증하고 문제를 탐색하는 보조적 시뮬레이터로 보는 것이 적절하다.</span>
